# KESHAV Semantic Registry

## Overview
This registry enforces the exact semantic meaning of terms utilized within the KESHAV dependency intelligence layer. It prohibits semantic drift by locking down terminology to specific definitions.

## Canonical Terms

### 1. `root_cause`
* **Allowed Meaning**: The singular, foundational task or dependency node within a trace graph that initiated a constraint failure, identified deterministically.
* **Prohibited Meaning**: A suggestion, a probabilistic guess, or an executable action.

### 2. `resolution_signal`
* **Allowed Meaning**: A structured, deterministic string identifying the precise condition required to unblock a failed task.
* **Prohibited Meaning**: A command, a policy enforcement directive, or a state mutation request.

### 3. `impact_score`
* **Allowed Meaning**: A deterministically calculated integer representing the severity and breadth of downstream dependency failures originating from a root cause.
* **Prohibited Meaning**: A business value metric, a subjective risk assessment, or an arbitrary weight.

### 4. `trace_id`
* **Allowed Meaning**: The immutable, globally unique identifier representing a single execution pipeline attempt provided by the upstream ecosystem.
* **Prohibited Meaning**: A locally generated ID or a mutable reference.

### 5. `intelligence`
* **Allowed Meaning**: The read-only diagnostic output generated by analyzing a dependency graph without side effects.
* **Prohibited Meaning**: Decision-making, governance, or automated remediation.
